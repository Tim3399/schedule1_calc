## Recovery boundary

`tools/recover_release_1_6_0.py --directory PATH` only verifies local files. Mutation
requires `--execute --confirm v1.6.0`, the expected repository, a manual workflow event
on `refs/heads/main`, and its job-scoped GitHub token. There is no generic version, run,
artifact or draft override. Regular tagged publication keeps its existing checks.

The recovery verifies artifact bytes, source versions, the single OCI manifest, config,
all twelve layer descriptors and their hashes, platform, labels and rootfs identities.
Remote checks bind them to the original run/attempt, successful quality jobs and unchanged
annotated tag. The specific draft must still be unpublished and empty, and the registry
version tag must be absent. Unexpected responses fail closed.

Publication uploads the exact original blobs and manifest through the OCI Distribution
API. It first verifies the manifest by digest, then repeats the version-tag absence check
before tagging those same bytes. This avoids Docker storage-driver conversion and
recompression. OCI requires support for the original uncompressed layer media type and
exact manifest storage; GHCR acceptance of this archive remains untested until execution.
See the [OCI image manifest specification](https://github.com/opencontainers/image-spec/blob/main/manifest.md)
and [OCI distribution push protocol](https://github.com/opencontainers/distribution-spec/blob/main/spec.md#pushing-an-image).

This one-off client accepts only HTTPS blob upload locations on GHCR and preserves
their opaque query parameters. Registry redirects fail closed instead of forwarding
credentials. GitHub asset readback may follow an HTTPS download redirect after dropping
authorization. Registry behavior requiring other upload hosts or redirects needs a new
review; the recovery does not silently relax this boundary.

Remote digests and release assets are read back and checked. The receipt retains the
original build run, revision, artifact hashes and config digest and records the verified
registry manifest digest separately. Only the source ZIP, release manifest and receipt
are attached to the existing draft before publication. No new build, draft deletion,
release replacement, version bump or `latest` update is part of this recovery.

The registry protocol has no standardized atomic create-only tag operation. Shared
workflow concurrency and a final absence check serialize this repository's publishers;
operators must keep external/manual writers away from `v1.6.0` during recovery. This is
not an atomic no-overwrite guarantee. Failure can retain untagged blobs, the image tag,
or partial draft assets. Stop and inspect that state; do not blindly rerun or delete it.
